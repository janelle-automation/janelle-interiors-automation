Janelle Interiors runs its studio in Houzz Pro, and that does not change. This system adds a purpose-built web application — a calm command center — that reads project activity from Gmail and Drive, understands it, and keeps every project, vendor, purchase order, and deadline continuously current. Then it drafts the follow-ups and writes the Monday report.

02

The build in three phases

PHASE 01
Prompt system

Prompt Studio

Up to 20 curated prompts across design, procurement / FF&E, client communication and admin — built from the studio's own spec sheets and proposals. They run inside the app on real project context. No copy-paste into an outside chatbot.

PHASE 02
Tracking layer

The live source of truth

The system reads email and Drive — including PDF quotes and confirmations — pulls out project, vendor, item and PO number, and keeps a live board current: active projects, vendor / PO tracker, awaiting-client, and spec gaps.

PHASE 03
Follow-up + reporting

Nudges & the Monday report

A nightly check for vendor silence, overdue approvals and slipping dates. Each becomes a Gmail draft for you to send — never auto-sent — plus a weekly Monday report summarizing the whole studio.

05

How data moves

Ingestion

Continuous
  1. Fetch new email and Drive files; download PDFs.
  2. Classify — relevant? which type?
  3. Extract structured data with Claude.
  4. Resolve to the right project, vendor, PO.
  5. Write to Supabase; push live to the board.

Follow-up

Nightly
  1. Scan rules: silence, overdue approvals, slipping dates, spec gaps.
  2. Draft each message with project context.
  3. Create a Gmail draft — never sent.
  4. Queue a card in the follow-up inbox.
  5. Log it so no nudge repeats.

Weekly report

Monday
  1. Aggregate the week's activity.
  2. Summarize as a narrative with Claude.
  3. Publish in-app with an optional draft copy.
  4. Notify the team it's ready.
06

What the weekly report covers

Generated every Monday, and on demand — the whole studio in one read.

  • Pipeline movement — projects that changed stage, and the count now in each.
  • Procurement — POs placed, confirmed, shipped and received; committed spend.
  • Overdue vendor follow-ups — who is silent, and for how long.
  • Awaiting client — approvals outstanding and their age.
  • At-risk dates — slipping deliveries and installs; installs coming up next week.
  • Spec gaps — items still missing information before they can be ordered.
  • Drafts pending review — follow-ups waiting to be sent.
  • Budget snapshot — committed vs. remaining, where budget data exists.

08

Data model

The single source of truth in Supabase Postgres. Every table carries an organization key and is protected by row-level security.

▪ projects ▪ vendors ▪ purchase_orders ▪ line_items ▪ documents ▪ emails ▪ follow_ups ▪ drafts ▪ spec_gaps ▪ reports ▪ prompts ▪ prompt_runs ▪ users / profiles ▪ integrations ▪ activity_log
09

Security & trust

  • Least-privilege OAuth — only the Gmail and Drive scopes needed; drafts, never send.
  • Revocable access — disconnect Google per user instantly; tokens encrypted at rest.
  • No write-back to Houzz Pro — the studio's system stays authoritative and untouched.
  • Human in the loop — every outbound message is a draft; the system never sends.
  • Row-level security — access enforced at the database, not just the interface.
  • Audit log — a record of everything read, extracted and drafted.

12

Open questions for the studio

Five answers shape the build. They carry over from the original brief.

  1. Email setup. Do vendor and client emails go to a shared inbox (projects@, info@), or does each member send from their own address?
  2. Houzz Pro export. Can the project list be exported as CSV? One sample of each notification email — new lead, client comment, invoice paid — would help tune extraction.
  3. Pipeline stages. Confirm the exact list of stages the studio thinks in.
  4. “Stuck” thresholds. How many days of vendor silence before a nudge? And for client approvals?
  5. Team & roles. The four to five people, and the access each role should have.
